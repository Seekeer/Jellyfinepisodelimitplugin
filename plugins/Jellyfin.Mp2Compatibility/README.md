# MP2 Audio Compatibility для Jellyfin

Самостоятельный серверный плагин: убирает MP2 из объявляемых Jellyfin Web поддерживаемых аудиокодеков. При Auto сервер может преобразовать MP2 в AAC, сохраняя совместимый видеопоток через copy. Исходные медиафайлы не меняются. Для AAC нужна поддержка браузером; перекодирование аудио и remux должны быть разрешены пользователю Jellyfin. Другие причины video encode (субтитры, bitrate и т. п.) по-прежнему действуют.

Версия 1.0.1.0 предназначена для Server/Web **12.2.0**, .NET 10. Проверяется SHA-256 исходного `main.jellyfin.bundle.js`, а не только строка версии. При другой сборке плагин пишет предупреждение и пропускает исходный Web без изменений. Он не обещает автоматической совместимости с будущими версиями; после выхода официального исправления может стать не нужен. Причина ошибки и upstream: https://github.com/jellyfin/jellyfin-web/issues/8836, https://github.com/jellyfin/jellyfin-web/pull/8823.

## Установка

1. В **Панель управления → Плагины → Репозитории** добавить каталог `https://raw.githubusercontent.com/Seekeer/Jellyfinepisodelimitplugin/main/manifest.json`, если его ещё нет. В **Каталог** выбрать **MP2 Audio Compatibility** и нажать **Установить**. Для ручной установки распаковать ZIP из GitHub Releases в отдельный каталог `MP2 Audio Compatibility_1.0.1.0` внутри каталога plugins Jellyfin.
2. Если раньше использовалась подмена Web-файлов, убрать только два mounts `web-overrides/12.2-mp2-aac-v1` из compose. Старый исправленный bundle имеет другую checksum; плагин намеренно не патчит его повторно.
3. Перезапустить/пересоздать Jellyfin. В списке установленных плагинов появится **MP2 Audio Compatibility**. В журнале должна быть строка `enabled for verified Jellyfin Web 12.2`.
4. Полностью обновить страницу Web и открыть фильм при **Auto**. Playback Info должен показывать H264 (direct), AAC для проверенного H264+MP2 MKV. Android/TV приложения со своим профилем не меняются.

Ни JavaScript Injector, ни File Transformation не требуются. Существующие плагины могут продолжать добавлять свои элементы в index. Плагин читает оригинальный bundle на старте, выдаёт исправленную копию через ASP.NET middleware и обновляет только URL main в HTML-ответе. В Web-каталог не пишет. Медиа/API-запросы не перехватывает.

## Отключение и откат

Отключить или удалить плагин в панели Jellyfin и перезапустить сервер. После полной перезагрузки страницы вернётся оригинальный профиль Web. Если требуется вернуть прежний файловый обход, восстановить два сохранённых mounts и пересоздать контейнер; исходные Web-файлы не затронуты самим плагином.

При обновлении Jellyfin сначала проверить совместимость: неизвестный hash означает безопасный пропуск патча, а не успешное исправление звука. Проверять журнал, фактический PlaybackInfo и FFmpeg `video copy + AAC`.

## Сборка и проверки

Из корня репозитория:

```bash
bash plugins/Jellyfin.Mp2Compatibility/build.sh
```

Нужен Docker; .NET SDK на хосте не требуется. Скрипт извлекает исходный bundle из остановленного контейнера закреплённого Jellyfin image, запускает .NET 10 тесты в SDK-контейнере с лимитами 2 CPU / 2 GiB и создаёт `artifacts/jellyfin-mp2/Jellyfin.Plugin.Mp2Compatibility-1.0.1.0.zip` и SHA256SUMS. Production контейнер, его БД и медиа при сборке не используются. Образ можно задать через `MP2_JELLYFIN_IMAGE`; неподдерживаемый bundle провалит проверку вместо создания ложной гарантии совместимости. `MP2_SDK_IMAGE` позволяет выбрать SDK image.

ZIP содержит только DLL плагина и `meta.json`; DLL Jellyfin/ASP.NET не включаются. Исходники находятся в этом каталоге. Сборка не публикует пакет автоматически. Release tags используют `mp2-v1.0.1.0`, чтобы не запускать выпуск Episode Limit; ZIP публикуется в GitHub Releases, а версия, URL и MD5 фиксируются в корневом `manifest.json`. После публикации пакет нельзя заменять без новой версии и checksum. CI проверяет тесты и сохраняет пакет как артефакт.

Тесты проверяют точный патч и отказ на неизвестной сборке, сосуществование с другим HTML-кодом, GET/HEAD/304, Range/Accept-Encoding, cache-busting HTML, base URL и восстановление response stream при исключении downstream. Реальная проверка воспроизведения против production выполняется отдельно от этих тестов.
